# init_project

Плагин для [Claude Code](https://claude.com/claude-code): инициализация документации проекта по опросному листу.

На выходе — **тонкий `CLAUDE.md`-роутер** и папка `docs/` в стиле Obsidian: короткие тематические файлы, связанные `[[wikilinks]]`, индекс-карта, история задач и журнал принятых решений.

Не привязан к языку и стеку: годится для кода на чём угодно, для проектов внутри чужой CMS/платформы, для интеграций и для не-кодовых проектов.

## Зачем

Монолитный `CLAUDE.md` разрастается до сотен строк, грузится целиком в каждую сессию, устаревает кусками и не ищется. Здесь наоборот: знание живёт в тематических файлах, а `CLAUDE.md` — карта «какой файл читать под какую задачу». Агент подтягивает нужный раздел по требованию, человек находит нужное глазами, обновляется всё точечно.

Второй смысл — **история задач**. Через полгода вопрос «почему код такой и что уже пробовали» стоит дороже, чем сам код.

## Как пользоваться

В корне папки проекта:

```
/init-project:init-project
```

Дальше по шагам:

1. **Разведка.** Если код уже есть — стек, команды, ветки, CI и формат коммитов вычитываются из репозитория и показываются на подтверждение. Того, что видно в `package.json`, не спрашивают.
2. **Опросный лист.** Восемь блоков, обязателен только первый; есть быстрый путь из девяти вопросов. «Не знаю» — нормальный ответ: вопрос уходит в раздел «Открытые вопросы», а не превращается в выдуманный факт.
3. **План на подтверждение** — какие файлы будут созданы.
4. **Генерация** документации и первой записи в истории задач.

Дальше по каждой задаче:

```
/init-project:task-log start INF-12345 Починить выгрузку остатков
/init-project:task-log done
```

При закрытии задачи скилл отдельно проверяет, что знание из неё переехало в `docs/`: грабли — в `pitfalls.md`, решение — в `decisions/`, факт о сервере — в `environments.md`.

## Что создаётся

```
CLAUDE.md                  ← тонкий роутер: минимум + карта документации
docs/
  index.md                 ← карта тем + «Открытые вопросы»
  project.md               ← что за проект, для кого, термины
  stack.md                 ← технологии, команды запуска/тестов/сборки
  architecture.md          ← из чего состоит, точки входа, запретные зоны
  environments.md          ← среды, деплой, где секреты, логи, бэкапы
  integrations.md          ← внешние системы и статус доступов
  workflow.md              ← задачи, ветки, коммиты, ревью, DoD
  conventions.md           ← правила кода и документации
  pitfalls.md              ← грабли: симптом → причина → что делать
  team.md                  ← кто есть кто
  decisions/               ← ADR: почему сделано так, а не иначе
  history/                 ← запись по каждой задаче + индекс
```

Файлы, для которых нет содержания, не создаются: тема без ответов висит в «Открытых вопросах», пока ответы не появятся.

## Принципы

- **Docs-first.** `CLAUDE.md` — роутер, не свалка.
- **Не выдумывать.** Открытый вопрос в индексе лучше правдоподобной догадки в файле: пробел видно, а догадке верят.
- **Не спрашивать то, что можно прочитать.**
- **Секреты — только указателем**, где лежат. Ни одного значения в репозитории.

## Другие агенты и другие модели

Скиллы написаны по открытому стандарту [Agent Skills](https://agentskills.io): во frontmatter обязательны только `name` и `description`, тело — обычный markdown без вызовов инструментов и MCP. Тот же `SKILL.md` подхватывают Codex, Cursor, Copilot, Gemini CLI, opencode и другие — подробности и способ подключения в [AGENTS.md](AGENTS.md).

Для чатов без доступа к файлам всё склеивается в один вставляемый текст:

```bash
./bin/bundle.sh > init-project-prompt.md
```

На моделях послабее страхует раздел «Если ты читаешь только этот файл» в `SKILL.md`: шесть железных правил, пять обязательных вопросов и минимальная структура — на случай, если агент не подтянул справочники из `references/`.

## Состав

| Скилл | Что делает |
|---|---|
| `init-project` | опросный лист → `CLAUDE.md` + `docs/` |
| `task-log` | завести, вести и закрыть запись по задаче, перенести знание в `docs/` |

Опросный лист целиком — [skills/init-project/references/questionnaire.md](skills/init-project/references/questionnaire.md).
