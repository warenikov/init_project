# Конвенции оформления (Obsidian-стиль)

Документация должна одинаково хорошо читаться в GitHub, в редакторе, в Obsidian и агентом, который подгружает один файл, а не весь репозиторий.

## Файлы

- **Один файл — одна тема.** Не помещается в один-два экрана — дели и связывай ссылками.
- Имена — латиницей, kebab-case, без пробелов: `environments.md`, а не `Среды и деплой.md`. Пробелы ломают ссылки в части инструментов, кириллица в путях — в части терминалов.
- Файл начинается с frontmatter, затем `# Заголовок`, затем ссылка назад на индекс.

```markdown
---
tags: [docs, environments]
updated: 2026-09-20
---

# Среды и деплой

← [[index]]
```

- `updated` обновляй при правке файла — по нему видно, чему уже нельзя верить.

## Ссылки

- Между файлами документации — `[[wikilinks]]` по имени файла без расширения: `[[architecture]]`, `[[history/index|история задач]]`.
- На код и внешние ресурсы — обычные markdown-ссылки: `[роутер](src/router.go)`, `[админка](https://...)`.
- Каждый файл связан хотя бы с одним другим. Файл без входящих ссылок не найдут.
- Ссылка на ещё не созданный файл допустима — это заявка на будущую тему, а не ошибка.

## Содержание

- **Таблицы вместо простыней.** «Что → где → когда читать» читается за секунды, абзац — нет.
- Команды — в блоках кода, копируемые целиком, с комментарием что делают.
- Каждый нетривиальный факт — с ответом на «почему», иначе его отменят при первой же уборке.
- Заглушки не создаём. Нечего написать по теме — файла нет, тема висит в «Открытых вопросах».
- Дата и источник у всего, что протухает: версии, адреса, контакты, договорённости.

## Индекс

`docs/index.md` — карта: таблица «тема → файл → когда читать» плюс раздел **«Открытые вопросы»** со списком того, что неизвестно. Открытый вопрос в индексе лучше выдуманного ответа в файле.

## Теги

Достаточно одного уровня: `docs`, `task`, `decision`, `pitfall`, плюс тема (`environments`, `security`, `payments`). Теги нужны для поиска по vault, а не для красоты — не плоди.

## Секреты

В документации — только указатель: «пароли БД — в менеджере паролей команды, раздел X», «токены — в переменных CI». Ни одного значения пароля, ключа или токена. Это касается и истории задач.
