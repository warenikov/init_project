# Что создаём

```
CLAUDE.md                  ← тонкий роутер: минимум + карта документации
docs/
  index.md                 ← карта тем + «Открытые вопросы»
  project.md               ← что за проект, для кого, стадия, глоссарий
  stack.md                 ← технологии, версии, команды: запуск, тесты, сборка
  architecture.md          ← из чего состоит, как связано, точки входа, запретные зоны
  environments.md          ← среды, адреса, деплой, где секреты, логи, бэкапы
  integrations.md          ← внешние системы и статус доступов
  workflow.md              ← задачи, ветки, коммиты, ревью, DoD, релизы
  conventions.md           ← правила кода и документации
  pitfalls.md              ← грабли: симптом → причина → что делать
  team.md                  ← кто есть кто, каналы связи            (если команда > 1)
  decisions/
    index.md               ← список ADR
    template.md            ← шаблон решения
    0001-….md              ← решения из ответов на C5
  history/
    index.md               ← таблица задач: в работе / завершённые
    template.md            ← шаблон записи по задаче
    YYYY-MM-DD-init.md     ← первая запись: инициализация документации
```

## Что обязательно, что по ситуации

**Всегда:** `CLAUDE.md`, `index.md`, `project.md`, `workflow.md`, `history/`.
**Почти всегда:** `stack.md`, `architecture.md`, `environments.md`.
**По ответам:** `integrations.md` (есть внешние системы), `team.md` (команда больше одного), `conventions.md` (есть договорённости сверх общепринятых), `decisions/` (по умолчанию да), `pitfalls.md` (создаём всегда, даже с одной записью — иначе первую грабли записывать будет некуда).
**Дополнительные темы из G2** — отдельными файлами: `mail.md`, `payments.md`, `permissions.md`, `seo.md`, `data-migration.md`, `security.md`, `performance.md`.

Не создавай файл, для которого нет содержания. Тема без ответов живёт в «Открытых вопросах» `index.md`, пока ответы не появятся.

## Специфика типов проектов

| Тип проекта | Что добавить обязательно |
|---|---|
| Проект на чужой CMS/платформе (Битрикс, WordPress, 1С, SAP) | Запретные зоны в `architecture.md`: где ядро, куда можно писать свой код, что затрётся при обновлении |
| Мобильное приложение | Подписи и сертификаты, сборки, публикация в сторы, минимальные версии ОС |
| Библиотека/SDK | Публичный API и политика совместимости, версионирование, публикация пакета |
| Данные/ML | Источники данных, где лежат датасеты и модели, воспроизводимость, приватность |
| Интеграция между системами | Схема «кто кого дёргает», форматы обмена, что делать при недоступности стороны, идемпотентность |
| Легаси в поддержке | `pitfalls.md` с первого дня, карта «где что лежит», что уже пытались чинить |
| Не-кодовой проект | Вместо `stack.md` — «инструменты и где что хранится»; остальное без изменений |
